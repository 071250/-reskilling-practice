誤り1
何行目: 16〜19行目（load_schedule 内の except Exception: return []）
何が起きる: ファイルがない、JSONが壊れているなど、どんな失敗でも黙って空のリストを返す。画面には「2026-10-02 の予定 0 件」と出るだけで、エラーは何も表示されない。
なぜ誤りか: 本当は「読み込めなかった」のに「予定が0件」に見えてしまい、利用者が原因に気づけない。理由を表示して止まるべき。
確かめること①〜⑤のどれで見つけたか: ③（エラーが表示されるか）。schedule.json を消して実行すると見つかる。

誤り2
何行目: 20〜22行目（events.sort(...) と、open(path, "w") で書き戻している部分）
何が起きる: 予定を表示するだけのはずが、実行するたびに schedule.json を並べ替えて上書き保存する。元のファイルの書式や順序が勝手に変わる。
なぜ誤りか: 「予定を表示する」という指示にない動作で、読み取り専用であるべきデータを書き換えている。書き込み中にエラーが起きれば、元のデータが壊れるおそれもある。並べ替えは表示のためにメモリ上でやれば足りる。
確かめること①〜⑤のどれで見つけたか: ④（指示に無いことをしていないか）。⑤でも、「なぜ読み込み関数が保存し直すのか」を3行で説明できないことから気づける。

誤り3
何行目: 34行目（format_event 内の event.get("location", "（場所なし）")）
何が起きる: location のキーが無ければ「（場所なし）」になるが、キーはあって値が空（"" や null）の場合は、そのまま空文字や None が出力される（例：@None）。
なぜ誤りか: 「場所なし」の表示が、キーがない場合にしか効かない。入力データの揺れに対応できていない。
確かめること①〜⑤のどれで見つけたか: ②（入力を変えても正しいか）。location を空にした予定を混ぜると見つかる。
